# Real-Time Sales Pipeline — Kafka + PostgreSQL

A practical real-time data engineering project built with **Python, Apache Kafka, and PostgreSQL**.

This project demonstrates how sales events are generated by a Python producer, streamed through Kafka, consumed by a Python consumer, processed as structured JSON data, and finally persisted into PostgreSQL.

---

## 📌 Project Overview

The project implements the following real-time data flow:

```text
Sales Event
     │
     ▼
Python Producer
     │
     │ JSON Message
     ▼
Kafka Broker
     │
     ▼
sales Topic
     │
     ▼
Python Consumer
     │
     ├── Decode JSON
     ├── Process Event
     └── Persist Data
     │
     ▼
PostgreSQL
     │
     ▼
sales Table
```

The main objective is to understand how **event streaming and relational database storage can work together in a real-time ingestion pipeline**.

## 📂 Project Structure

```text
Project/
│
├── producer.py
├── consumer.py
├── database.py
├── table.py
├── docker-compose.yml
└── README.md
```

### `producer.py`

Responsible for:

* Connecting to Kafka
* Accepting sales information
* Validating input
* Calculating order totals
* Creating structured JSON events
* Publishing events to the `sales` topic

### `consumer.py`

Responsible for:

* Connecting to Kafka
* Joining the configured consumer group
* Subscribing to the `sales` topic
* Polling for incoming events
* Decoding JSON messages
* Processing sales data
* Inserting events into PostgreSQL
* Handling duplicate order IDs
* Gracefully shutting down the consumer

### `database.py`

Responsible for:

* Loading PostgreSQL configuration
* Connecting to PostgreSQL
* Creating the `realtime_sales` database

### `table.py`

Responsible for:

* Connecting to the target PostgreSQL database
* Creating the `sales` table
* Defining columns and constraints

### `docker-compose.yml`

Provides the local Kafka environment required by the project.

## ⚙️ Kafka Configuration

Kafka broker:

```text
localhost:9092
```

Kafka topic:

```text
sales
```

Consumer group:

```text
my-simple-group
```

Consumer offset configuration:

```text
auto.offset.reset = earliest
```

---

## 📦 Sales Event Structure

The producer creates a structured sales event:

```json
{
  "order_id": 1001,
  "product": "Bread",
  "price": 150,
  "quantity": 2,
  "total": 300
}
```

The total is calculated as:

```text
price × quantity
```

Example:

```text
150 × 2 = 300
```

---

## 📤 Producer Workflow

The producer accepts sales information through the terminal.

The flow is:

```text
User Input
   ↓
Input Validation
   ↓
Calculate Total
   ↓
Create JSON Payload
   ↓
Convert to UTF-8
   ↓
Publish to Kafka
```

Example:

```text
Order ID : 1001
Product  : Bread
Price    : 150
Quantity : 2
Total    : 300
```

The event is published to:

```text
sales
```

---

## 📥 Consumer Workflow

The consumer continuously monitors the `sales` topic.

The processing flow is:

```text
Kafka Message
      ↓
UTF-8 Decode
      ↓
JSON Decode
      ↓
Python Dictionary
      ↓
Read Sales Fields
      ↓
PostgreSQL Insert
```

Example consumer output:

```text
Received

Order ID    : 1001
Price       : 150
Product Name: Bread
Quantity    : 2
Total       : 300

Saved to PostgreSQL
```

The consumer can be stopped gracefully using:

```text
Ctrl + C
```

---

## 🗄️ PostgreSQL Database

Database:

```text
realtime_sales
```

Table:

```text
sales
```

### Table Schema

| Column     | Type    | Constraint  |
| ---------- | ------- | ----------- |
| `order_id` | INTEGER | PRIMARY KEY |
| `product`  | VARCHAR | NOT NULL    |
| `price`    | INTEGER | —           |
| `quantity` | INTEGER | —           |
| `total`    | INTEGER | —           |

The `order_id` primary key prevents duplicate order identifiers from being stored as separate records.

---

## 🔄 End-to-End Pipeline

The core project flow is:

```text
Python Producer
       ↓
JSON Sales Event
       ↓
Kafka Broker
       ↓
sales Topic
       ↓
Consumer Group
       ↓
Python Consumer
       ↓
JSON Processing
       ↓
PostgreSQL INSERT
       ↓
sales Table
```

This architecture demonstrates a simplified real-time data ingestion pipeline.

---

## ♻️ Duplicate Order Handling

The PostgreSQL insert uses conflict handling for duplicate order IDs.

Conceptually:

```text
Incoming Order
      ↓
Check order_id
      ↓
Existing?
   ├── No  → Insert
   └── Yes → Ignore duplicate
```

This prevents duplicate primary-key insertion from terminating the ingestion flow for the same order identifier.

The Python applications communicate with Kafka through:

```text
localhost:9092
```

Using Docker provides a convenient local environment for running Kafka without manually configuring the Kafka server directly on the host operating system.

## ▶️ How to Run

### 1. Start Kafka

Start the Docker Compose Kafka environment from the project directory.

### 2. Prepare PostgreSQL

Make sure PostgreSQL is running and the required credentials are available through `.env`.

### 3. Create the Database

Run the database setup process to create:

```text
realtime_sales
```

### 4. Create the Table

Create:

```text
sales
```

with the required schema.

### 5. Start the Consumer

Run:

```bash
python consumer.py
```

The consumer will subscribe to the `sales` topic and wait for events.

### 6. Start the Producer

In another terminal:

```bash
python producer.py
```

Enter sales information through the prompts.

### 7. Verify PostgreSQL

After an event is consumed, verify that the corresponding record exists in:

```text
realtime_sales.sales
```

Publishes sales events to Kafka.

Receives and processes events from Kafka.

The Kafka server that receives and delivers records.

### Topic

A named stream where records are published.

This project uses:

```text
sales
```

### Message / Record

An individual sales event sent through Kafka.

### Consumer Group

A logical group associated with the consumer:

```text
my-simple-group
```

### Offset

A position associated with records in Kafka partitions and used by consumers to track their progress.
